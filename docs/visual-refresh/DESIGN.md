# Git Cockpit · 全站视觉改版 · 设计决策说明

> 本文档是 `docs/visual-refresh/` 原型的配套设计说明，面向评审人与未来生产实施者。
> 配套文件：`REVIEW.md`（质量审查报告）、`README.md`（实现说明与取舍点）。
> 线上事实以代码为准：全部令牌见 `assets/tokens.css`，公共组件见 `assets/chrome.css`。

---

## 1. 背景与目标

### 用户诉求

Git Cockpit 是基于 MCP 的 Git 可视化操作工具（本地常驻服务的 Web 管理界面，Vue 3 + Element Plus 深色开发者工具）。本次改版范围是**全站视觉刷新**，评审用纯静态高保真原型，不连后端。立项时梳理出四个痛点：

1. **品牌辨识度弱**：界面没有可一眼识别的签名语言，换一套 UI 框架也难以察觉。
2. **信息密度与效率**：开发者工具每天凝视数小时，控件与行高偏松，一屏能处理的信息太少。
3. **新手可发现性**：Git 概念（冲突、rebase、reflog）对新手是黑盒，需要语义色与状态信号引导。
4. **暗色体验**：生产版本暗色层次与对比度未精细校过，长时间阅读疲劳。

### 风格借鉴与独立语言

参照系是 Linear / GitHub / Raycast 三类高完成度深色产品。借鉴的是**完成度标准**（分层表面、克制用色、精密排版），但刻意不复制任何一家的签名元素——最终走出一条自己的语言：Linear 的基底纪律 + Git 语义色编码 + 「驾驶舱」仪表化状态语言。

### 产出形态与评审方式

产出为纯静态 HTML 原型（`index.html` 枢纽 + 7 个路由页 + 首轮对比留档 `prototype.html`），浏览器双击即开。视觉内核提供**双主色实时对比**后再定终选：签名 teal 青绿（主推）与极地白（备选）两套并存，切换方式见第 9 节。

## 2. 设计主张五条

| # | 主张 | 含义 |
|---|---|---|
| 1 | **驾驶舱** | 这是 Git 的座舱：连接状态、任务进度、分支态势如仪表盘般常驻可读，用户随时知道「现在飞得怎么样」，而不是靠翻页面找状态。 |
| 2 | **精密密度** | 12px 正文、28px 控件不是权宜之计，是**资产**——信息密度即效率。为此专设 10px 微标签档与等宽行高纪律，并全程守住对比度承诺（见第 8 节）。 |
| 3 | **冷光暗色** | 发光是稀缺资源，绝大多数界面应当是实底分层。发光只授予三种关键状态信号，且 alpha ≤ .35，冷光而非彩光。 |
| 4 | **语义色即导航** | 颜色承担导航职责而非装饰：**绿**=分支/新增/通过，**红**=冲突/删除/失败，**紫**=合并，**琥珀**=rebase/警告/待确认。用户扫颜色即可定位注意力。 |
| 5 | **人机同台** | AI 与人类操作同一份仓库，界面必须让人类始终保有确认权。**干跑确认条**（危险操作前展示将执行的命令与影响文件）是安全感的核心符号。 |

## 3. 设计系统选型：Linear 基底 + 5 处关键偏离

以 Linear 为风格基底深度定制，五处刻意偏离构成独立性：

1. **签名色换 teal**：避开 GitHub 蓝与 Linear 紫的认知红海，主推 teal 青绿 `#14c8b8` 一族；备选极地白 `#eef4f9` 供对比评审（见第 9 节）。
2. **表面沿用深蓝黑三分层**：`--gc-page #0e1218` / `--gc-card #161b24` / `--gc-overlay #1d2434`，纯深蓝黑而非中性灰，与冷光主张同构。
3. **新增「发光即信号」系统**：Linear 几乎不用发光；本系统把 glow 制度化——只存在于任务脉冲条、连接 tag 点、干跑条琥珀顶缘/呼吸、冲突未决行、聊天球 confirm 外环等状态信号处，`--gc-glow*` 变量统一管控 alpha ≤ .35。
4. **密度再压一档**：Linear 控件约 32px；本系统压到 **28px**（`--gc-control` / `--gc-row` / `--gc-input`），行高 28px 配 12px 正文，diff 全域等宽。
5. **无对标组件语言**：diff/日志全域等宽 + Git 语义色编码；干跑确认条、冲突选边行、任务脉冲条、连接状态 tag 三态等均为本产品独有组件，无任何参照实现可抄。

## 5. 品牌

### Logo：⌘ 基因重构

以命令键 ⌘ 的**四环结**结构为基因重构，不使用现成字形：24×24 viewBox；四角各一个整圆（r=3.4），切向连边相连；stroke 2，round cap / join；16px 尺寸下仍可辨。使用纪律：**顶栏只放符号**，`Git Cockpit` 字标仅在 `index.html` 品牌区与符号并列出现一次。

### 图标系统

- 24 网格、stroke 1.5、round cap / join，自绘字典 `assets/icons.js`，47 键全部被引用（0 死键、0 缺失引用）。
- 注入后 DOM 中为同文档内联 SVG，无第三方图标库、无 emoji；8 页图标笔触完全一致。

## 6. 标志性组件语言

| 组件 | 语言 |
|---|---|
| **连接状态 tag 三态** | 正常（静态点）/ 连接中（呼吸点 + 弱底）/ 失败（红点 + 红字），三态置于顶栏，驾驶舱主张的落地件。 |
| **任务脉冲条** | 双段结构：已完成段纯色 + 活跃扫描段（纯色平移，非渐变），完成/失败各有终态色。 |
| **干跑确认条** | 琥珀顶缘 + `is-pending` 时左边框呼吸 + 命令预览与影响文件列表；「未确认不安置」——没有确认就没有执行。确认态顶缘转实、呼吸停止。 |
| **冲突选边行** | 行号 + OURS 栏 + THEIRS 栏（chip 与代码内容同栏，见 README-1）；**未决=红边、已决=绿边**，选中侧 chip 高亮。 |
| **实底 dock** | 左侧竖向导航整体实底（不透明、无玻璃），激活项顶部 2px 指示条 + 高亮底；镶标数字徽章。 |

## 7. Anti-Slop 十条禁令

1. 禁一切渐变（linear/radial）——0 处。
2. 禁 >10px 圆角——0 处（tag 4 / 控件 6 / 卡片 6 / 玻璃 10；chat-ball 与状态点为功能圆形，已豁免）。
3. 禁毛玻璃出状态展示区——`glass-card` 仅 dashboard 状态展示区使用，效率敏感区全实底。
4. 禁彩色投影；发光仅限信号且 alpha ≤ .35——彩色投影 0 处；发光枚举见 README 自检表（含「聊天球 confirm 外环」共 6 处信号位）。
5. 禁 emoji——0 处；`✓/✕` 字符亦全部替换为 SVG 图标。
6. 禁装饰性营销元素——无 hero 大图、无无意义插画、无营销文案。
7. 禁 >700 字重与 >16px 正文——字重 0 处越线；正文最大 12px，20px 仅空状态标题（规格允许）。
8. 本期禁浅色主题——仅深色一套皮肤 × 双主色变量。
9. 禁滑动转场——仅 micro/open/pop 时长内的淡入与位移过渡。
10. 禁顶栏与 dock 用玻璃——顶栏、dock 全部实底分层。

## 9. 双主色评审指南

**切换方式**：
- 任意页**左下角浮动切换器**（两个色块，点击即切）；
- `index.html` 顶部**显眼分段控件**（带当前方案高亮与「当前：teal 青绿 / 当前：极地白」徽标）。
- 选择写入 `localStorage`（键 `gc-accent`），跨页保持，防首屏闪烁脚本内联于各页 head。

**对比重点**——这两处对主色饱和度最敏感：
1. `status.html`：**分支树当前行**与**更改选中行**；
2. `merge.html`：冲突 **OURS chip** 与**矩阵干净格**。

**极地白的已知取舍与兜底**：高亮态与主文字层级更依赖 glow 与弱化底区分。已用变量隔离兜底（`--gc-glow` / `--gc-accent-weak` / 热力阶冷色阶 / OURS 绿结构色），并在 `status.html` 增加极白专属规则：分支树当前行与更改选中行**额外加 2px 左侧 accent 指示条**，不依赖底色深浅判断。仍需用户确认可辨性达标后终选。

## 10. 生产落地路径（给未来实施者）

1. **令牌整体替换**：`assets/tokens.css` 的 `:root`（teal）与 `html[data-accent='white']` 两段，可整体替换生产 `packages/web/src/theme.css` 的 `:root`（约 17–68 行）与 `html.dark`（约 71–93 行）区块。Element Plus dark css-vars 之上的约 700 行覆盖层逻辑可保留，仅需将其中的字面值改引用新令牌。
2. **最大剩余工作量：diff2html 段**。生产 `theme.css` 中 diff2html 段实测 **207 行、72 处 `!important`**（自 612 行起，含单栏 line-by-line 段），本次未纳入原型范围，落地时需单独对齐新令牌——建议新写一段 diff 令牌映射，再逐条收敛 `!important`（目标 ≤30 处）。
3. **玻璃拟态分区规则**：仅状态展示区可用 `--gc-glass-*`；效率敏感区实底。落地时按同样分区维持。
4. **窄屏策略待定**：聊天面板 <1100px 收起策略未定，落地时需产品决策。
5. 原型 `chrome.css` 的组件样式（顶栏、tag、脉冲条、dock、chip、干跑条、冲突行）可翻译为 Vue 组件样式，选择器语义可直接映射。

## 11. 已定 / 待定清单

**已定**
- 视觉语言五条主张（驾驶舱 / 精密密度 / 冷光暗色 / 语义色即导航 / 人机同台）；

- 双主色并排评审机制；

- Anti-Slop 十条门禁全 PASS，质量门通过（见 REVIEW.md）。

**待定**
- 生产落地方式与排期（含 diff2html 债务、窄屏策略）——落地计划见 docs/visual-refresh/PRODUCTION.md；
- Google Fonts：原型**未启用任何外部字体请求**（`'Inter'`/`'JetBrains Mono'` 仅在 font-family 降级链中声明，未接入 CDN），ZIP 完全离线可用；生产如需真字体，另行内联 woff2 或改为系统字体栈。
