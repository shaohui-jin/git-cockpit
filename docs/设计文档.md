## 1. 项目概述

**项目名称**：Git Cockpit（展示名；npm 包：`@shaohui_jin/git-cockpit-mcp-server`，CLI：`git-cockpit`，完整命名规范见 11.1 节）  
**项目定位**：基于 MCP 的 Git 可视化操作工具：Web 界面 + 供外部 Agent 调用的 MCP 工具，支持多仓库与安全的 Git 操作。选边不由模型做。可选在同一 Web 内聊天（`/api/chat`，SDK 只在 server；模型 Key 在设置页，与 MR Token 同级）；桌面 Electron 是可选宿主，不是第二套后端。方案见 [聊天壳方案.md](./聊天壳方案.md)。  
**当前形态**：一个 npm 包三种入口——**MCP Server**、**Web**、**CLI**（`git-cockpit start` / `mcp`），另可选桌面窗壳。**不做** Cursor/VS Code 扩展。配 MCP **不等于**打开聊天页。

**核心价值**：
- **工具给宿主用**：Cursor、Claude 等通过 MCP 调用 `git_status` 等；也可在本机 Web/桌面聊天页调同一套手（确认闸在 `/api/chat`）。
- **可视化交互**：浏览器内完成暂存、提交、分支、stash、拉取/推送等。
- **安全可控**：高风险默认禁用；写操作 dry-run 预览 → 确认 → 执行；高危自动备份；审计日志。
- **唯一后端**：Web 与 MCP 共用 Runtime / GitService，队列与锁全局生效。

## 2. 目标用户与使用场景

### 2.1 目标用户
- 前端/全栈开发者，希望在聊天窗口里用 Agent 辅助 Git（通过 MCP 工具）。
- 不熟悉 Git 命令行的开发者，需要可视化界面。
- 团队协作者，需要审查历史、查看差异。
- 希望用 MCP 把 Git 接进 Agent 工作流的用户（在 **编辑器聊天窗口** 里操作，不是打开 Cockpit 内置对话）。

### 2.2 典型场景
1. **宿主辅助提交**：用户在聊天窗口说「看看当前改动并提交」，宿主模型调用 `git_status`、`git_diff`，再调用 `git_add` 和 `git_commit`。
2. **历史分析**：宿主调用 `git_log` / `git_show`，在对话里回答关于代码变更的问题。
3. **可视化手动操作**：用户在 Web 状态页勾选文件、暂存、提交、推送；操作前弹出 dry-run 预览确认框。看提交记录在状态页切到「提交」，不必另开一页。
4. **选择性 stash**：勾选部分文件 stash（对应 IDE Shelve），可 apply / pop / drop，并查看 stash diff。
5. **多仓库切换**：打开多个本地仓库。工作台卡片按拖拽 `pin_order` 排列（新仓在队尾）；`last_opened_at` 只显示在卡片上，并作为 MCP 未指定仓时的默认仓。状态/合并视图跟随当前仓库刷新。
6. **权限治理**：在设置页开关高风险工具、配置审批名单；被拒操作会引导前往设置。
7. **合并预演、矩阵、选边与落盘**：网页选 `into`（合入目标 / ours）与 `from`（我的分支 / theirs），`merge-tree` 预演不改工作区；多分支用矩阵扫描、可建议合入顺序。从矩阵进单对：三栏选边后「完成冲突处理」只写入本地 `merge/…`（`push: false`），再回矩阵看「已解决·本地」，再在矩阵上推送该临时分支、申请 MR。从侧栏直接进单对：干净可落盘并推送；有冲突必须人在网页选边。宿主聊天窗口只预演；有冲突给 `webUrl`，**不要**传 `files` 选边。开 PR/MR 先过 `mergeGate`（冲突/未落盘不能开，含 dry_run）。不把多条 from 合成一条批量分支。

## 4. 功能范围

### 4.1 MCP 工具集（供宿主 Agent 与 Web 共用）

工具定义在 `packages/core/src/capabilities/git/`（`TOOL_DEFS` 汇总于 `git/index.ts`），参数 Schema 在 `packages/core/src/capabilities/schemas.ts`（zod）；mcp-server `tools/index.ts` 再导出并 `registerAll`。每个工具均支持可选 `repoPath`（缺省为最近打开仓库）与写操作 `dryRun`。MCP 大结果默认摘要：`git_diff` / `git_show` / `git_merge_rehearse` / `git_file_content`（超 64KB）不回完整正文，要正文请加 `path` 或 `detail=true`。网页 GET 仍是全文。

#### 只读工具（默认开放）

| 工具名称 | 功能描述 |
|---------|---------|
| `git_status` | 工作区状态：分支、已暂存/未暂存/未跟踪、冲突、领先/落后上游、`operation`（`none` / `merge` / `rebase`，看 `MERGE_HEAD` / `REBASE_HEAD`） |
| `git_log` | 提交历史（分页、作者/路径/范围/`--all`） |
| `git_diff` | 工作区/暂存区/提交范围差异；大 patch 默认截断 2MB |
| `git_show` | 某次提交元信息 + 相对父提交的 diff |
| `git_branch_list` | 本地/远程分支；本地带 upstream 与 ahead/behind |
| `git_tag_list` | 标签（按创建时间倒序） |
| `git_remote_list` | 远程名称与 fetch/push URL |
| `git_file_content` | 指定提交中文件内容（大文件截断 2MB） |
| `git_graph` | 全部分支提交列表（hash/parent/refs），给线性历史；状态页 G6 请用 `git_branch_graph` |
| `git_branch_graph` | 分支 tip DAG（for-each-ref + rev-list --parents）；可选 `into`/`from` 返回 lineage（merge-base 与两侧独有提交数） |
| `git_reflog` | HEAD reflog |
| `git_backup_list` | 高危操作备份分支 / stash |
| `git_stash_list` | 全部 stash 记录（`stash@{n}` / 说明 / 时间） |
| `git_stash_show` | 查看某条 stash 的 diff（不改仓库） |
| `git_merge_preview` | `merge-tree` 预演把 `from` 合入 `into`（不改工作区）；返回是否干净、冲突列表、`situation`、有冲突时 `webUrl`。Git ≥ 2.38 |
| `git_merge_rehearse` | 预演 + 冲突文件 diff3 正文（ours/theirs/base）。网页三栏选边；MCP **不**传 `files` |
| `git_merge_blame` | 对单个冲突文件两侧 tip 跑 `git blame`（不改工作区）；返回作者/说明/时间。只读，不是选边 |
| `git_mr_prepare` | 只读：源/目标、浏览器创建页、本机 gh/glab、审核人、`template`、`mergeGate`。冲突/未落盘时 `ok=false` 仍返回 URL，不许 create。Token 不进参数 |
| `git_merge_survey` | 批量预演：`intos × froms` 每对 `merge-tree` 一次，整批只 fetch 一次；只返回 outcome、冲突路径、已有 `merge/*` 临时分支。格子 >20 或 `async=true` 时后台 Job，回 `jobId`。组合数超过 `MAX_SURVEY_PAIRS`（**200**）时同步拒绝，错误码 `SURVEY_TOO_LARGE`，文案「组合数 N 超过上限 200，请缩小分支范围」。不生成正文、不带格子颜色。单格失败不影响其余格 |
| `git_repo_overview` | 已打开仓库脉搏：分支、脏计数、ahead/behind、`operation`、本地 `merge/*` 数、近 12 周提交总数。默认不含每日格子（`detail` 才回）。不回 diff。不依赖当前仓 |
| `git_job_list` / `git_job_get` | 后台任务摘要 / 详情（日志 + result） |
| `git_worktree_list` | 列出本仓 git worktree（含主工作区）。只读。不要把 linked worktree 当成第二套工作区做 merge |
| `git_merge_order` | 建议多个 from 合入同一 into 的顺序：对象库内结果树 + `commit-tree` 游离 commit，不改工作区；返回建议顺序、cleanPrefix、从哪步开始要人工 |

宿主可插入 MCP Prompt（正文与 README「Agent 该怎么用」相同，不另写流程）：`safe_commit`、`merge_preview_apply`、`workspace_continue`、`open_mr`。只读 Resource（不进审计）：`git-cockpit://repos`（与 `git_repo_overview` 同摘要）、`git-cockpit://repo/current`（最近打开仓工作区计数）、`git-cockpit://jobs`、`git-cockpit://jobs/{id}`（日志尾）。

#### 写操作工具（默认开放，需预览/确认）

| 工具名称 | 功能描述 |
|---------|---------|
| `git_add` | 暂存指定路径；空则暂存全部 |
| `git_unstage` | 取消暂存（`git reset HEAD --`） |
| `git_commit` | 创建提交；可限定 paths、`allowEmpty` |
| `git_checkout` | 切换分支；本地更改会被覆盖时拒绝 |
| `git_branch_create` | 创建分支（可选 startPoint） |
| `git_branch_delete` | 安全删除（`-d`，未合并则拒绝） |
| `git_merge` | 普通合并；冲突时返回明确错误 |
| `git_merge_abort` | 中止当前工作区 merge（不是预演收尾） |
| `git_merge_continue` | 继续工作区 merge。网页可带 `files` 写入工作区并 add；MCP **禁止**带 `files` |
| `git_rebase_abort` | 中止当前工作区 rebase |
| `git_rebase_continue` | 继续工作区 rebase。网页可带 `files`；MCP **禁止**带 `files` |
| `git_pull` | 非强制拉取 |
| `git_fetch` | `fetch --prune --no-tags`；改远程跟踪引用，不改工作区 |
| `git_push` | 非强制推送；可指定 `remote` / `branch`（矩阵推送本地 `merge/…` 时不切换当前工作区）。被拒时提示先 pull |
| `git_tag_create` | 轻量/附注标签 |
| `git_stash` | stash；可 `-u`、可 `paths` 选择性暂存 |
| `git_stash_apply` | 应用 stash（保留记录） |
| `git_stash_drop` | 删除 stash 记录 |
| `git_stash_pop` | 恢复并删除该条 stash |
| `git_apply_resolve` | 独立 worktree 落盘：基于 `into` 建临时分支、merge `from`、可选 push。主工作区不切换。仅干净合并可无 `files`；冲突选边只在网页传入 `files`。MCP 禁止 `files`（`AGENT_NO_RESOLVE`）。矩阵流程传 `push: false` + `keepLocal: true` 只留本地 |
| `git_job_cancel` | 取消进行中后台任务（克隆杀进程并删不完整目录） |
| `git_worktree_add` | 独立目录 `git worktree add`；路径须绝对且不在主工作区内；非空 `allowedRepos` 时须在白名单下。不切换主工作区 |
| `git_worktree_remove` | `git worktree remove`；不能移除主工作区；可选 `force` |
| `git_mr_create` | 先过开单闸（冲突/未落盘/临时枝未推一律拒绝，含 dry_run），再按设置开 PR/MR：`token`、`cli`、`browser`。启用正文规范时必须传 `fields`，服务端渲染 body。`browser` 返回创建页 URL + 渲染正文（请复制粘贴），不写到远程，规范启用时提示改用 Token/CLI。GitLab 审核人用户名会解析成数字 id。Token **不进**工具参数 |

#### 高风险工具（默认禁用 + 需审批，执行前自动备份）

| 工具名称 | 功能描述 |
|---------|---------|
| `git_reset_hard` | `reset --hard` |
| `git_clean` | `clean -df` |
| `git_push_force` | `--force-with-lease`（非裸 `--force`） |
| `git_branch_delete_force` | `branch -D` |
| `git_rebase` | 变基（开始一次 rebase） |

`git_rebase_abort` / `git_rebase_continue` 是 **write**（结束已经开始的 rebase），不在默认禁用名单。开始变基才是 `git_rebase`（dangerous）。

默认配置：上述 5 个同时出现在 `disabledTools` 与 `requireApprovalFor`。要真正执行，必须在设置中**同时移出禁用名单与审批名单**。

Web 写操作走同一套工具，入口为 `POST /api/repos/:id/tools/:tool`。状态页已接的按钮：add / unstage / commit / checkout / branch_create / branch_delete（及强制删）/ pull / fetch / push / push_force / stash 全家 / worktree 列表与添加删除 / reset_hard / clean / 工作区 `git_merge`（含 continue/abort）/ tag / rebase（含 continue/abort）。合并页：预演走 GET `/merge/rehearse`（可先 fetch）；矩阵进单对后 `git_apply_resolve`（`push: false`）；矩阵上再 `git_push` 指定临时分支、`git_mr_create`。侧栏单对可落盘并推送。工作区 `git_merge` 与左侧「合并」页的 merge-tree 预演不是同一件事，按钮文案写成「工作区合并」。

### 4.2 Web 可视化界面（已实现）

侧栏分两截：**干活**与 **系统**（任务 / 操作日志 / 设置）。干活区在已配置模型 Key 时为 聊天 / 工作台 / 状态 / 合并，未配置时为 工作台 / 状态 / 合并 / 聊天。任务有进行中角标。没有「历史」入口；看提交走状态页。打开应用仍进工作台，不默认进聊天。

- **工作台**（`/` → `/dashboard`，`/repos` 重定向）：打开本地路径、克隆入口、多仓脉搏。默认**卡片墙**：摘要数字筛卡住（不可用 / merge|rebase / 冲突）/ 有更改 / 未同步（↑↓ 或本地 `merge/*`），一仓只进一类；卡上名称、分支、该亮的标记，底栏近 12 周按日热力（周一为一周起点，7×12，`git log --all --date=short`，不读 diff）。单击设当前仓（当前卡抬起，其余压暗）；拖拽改顺序并写入 `pin_order`。进入去状态，合并去 `/merge`。卡上显示上次打开时间。打开成功后留在工作台。数据：`GET /api/repos/overview` 与 `git_repo_overview`（MCP 默认只留 `activityTotal`，`detail` 才回 `activity[]`）。页面只有「打开本地仓库」与「仓库一览」两块，纵向铺满（一览区滚动）。不轮询，进页或点刷新再拉。卡上可勾选，点「刷新远程」对选中仓各起一个 `POST /api/jobs` `kind=fetch`（同仓 survey/fetch 互斥；不改工作区）。**克隆到本地**：填 URL（禁止夹带 token / userinfo）与绝对空目录，`POST /api/jobs/clone` 起后台任务；目标路径须过 `allowedRepos`。提交后右上角 Notification（点击进 `/jobs?id=`），不在工作台堆任务列表。
- **任务**（`/jobs`）：左右分栏，**无抽屉**。左栏宽约 360px：按 `startedAt` 倒序，进行中始终置顶；顶上芯片筛全部 / 进行中 / 失败 / 成功（带数量）。每行：状态、kind 标签（克隆 / 矩阵扫描 / 抓取）、相对时间、标题（克隆为 URL→路径，抓取/扫描为「操作 → 仓库路径」，旧任务 title 不含路径则用 `repoPath` 补上）、日志尾或错误。**不按 kind 分组**。点一行写入 `?id=` 并 `GET /api/jobs/:id` 拉详情；右栏常驻该任务日志（`logs.join('\n')`，处理 `\r`）。进页若带 `?id=` 则选中该条。当前筛里没有已选任务时，改选可见第一条；筛空则清空 query。无任何任务时提示去工作台克隆；当前筛无匹配时提示「没有这类任务」；未选中时右栏提示点左侧。进行中可 `POST /api/jobs/:id/cancel`（克隆杀进程并删除不完整目标目录）。失败且 kind=clone 可改 URL/路径重试。`git clone --progress` 用 spawn（不走当前仓 GitService 队列，simple-git.clone 会整段缓冲）。任务写入 SQLite `jobs`（进行中约 200ms 落盘，结束强制写；旧 `clone_jobs` 启动时迁入后删除）；进程重启时 `running` → `error`（「服务重启，任务中断」）。SSE `job-progress` 约 200ms 节流，漏掉的 `chunk` 会攒到下次推送；结束只推 `ok`/`error`，前端再拉详情，并再弹成功/失败 Notification（点击进该任务）。成功后 `repoManager.open` 加入列表。侧栏「任务」显示进行中数量。
- **状态视图**（`/status`）：右上角切 **工作区 | 分支图 | 提交**（只换右侧，不换仓）。  
  - **工作区**（写操作）：左侧分支树（本地 + 远程分组，↑↓ 同步信息，数据来自分支 store；**双击切换**；**右键菜单**切换 / 拉取推送 / 删除，单例、宽 `--gc-ctx-menu` 100px）。右侧：未暂存 / 已暂存 / 未跟踪 / 全部；**更改列表按路径树**（目录在前，叶子为文件名；保留 A/M/? 方块与暂存/差异操作；目录勾选覆盖子文件；行高 `--gc-line`、左右 `--gc-pad`）。勾选后暂存或选择性 stash；文件 diff 抽屉（DiffViewer）；stash / 备份 / worktree / reflog 合在「记录」卡片里与「更改」对半铺满。提交、建分支、**工作区合并**、Fetch、打标签、硬重置、清理未跟踪、变基、强制推送。worktree 只提供列表/添加/删除，不在 linked worktree 里做 merge。工作区处于 merge/rebase 时告警条提供「完成选边并继续 / 中止」，三栏写回当前工作区（index `:1/:2/:3`），**不是** `git_apply_resolve`。  
  - **分支图**：**收起左树、右侧铺满**。tip DAG（`for-each-ref` + `rev-list --parents`，G6 dagre），节点是各分支 tip 不是每条 commit，与 Git Insight 同口径。图上方可选 into/from **对比**，有共同祖先时画布切成三节点 Y 图（分叉点 / 线上 / 我的）。不在此模式切分支。  
  - **提交**（`CommitLogPanel`）：同样收起左树、铺满。范围：当前分支（HEAD）/ 全部分支 / 指定分支（面板内树选，可含远程）；路径过滤、条数 20/50/100。搜索条按内容高度，表格占满剩余高度并滚动。点击行打开差异抽屉：标题行（`--gc-line`）为提交说明 + 短 hash；下一行 meta：作者 · 时间 · refs（过长省略）· 文件数与 +/-（REST 把 `stats.insertions/deletions` 摊到顶层）。有 body 时默认收起。不从已收起的左树点选来过滤（避免与工作区双击切换同一套手势）。独立路由 `/history` **已删除**，无 redirect。
- **合并视图**（`/merge`，侧栏一项；`/matrix` 重定向到 `?mode=matrix`）：页内切换 **单对预演 | 矩阵**，状态在 `useMergeSessionStore`（内存，换仓清空，不写 SQLite）。
  - **单对**：`BranchTreeSelect` 选合入目标 `into`（线上 / ours，远程组优先）与我的分支 `from`（theirs）；可选非交互 fetch；预演得到 `situation`。有冲突时 `ConflictResolvePanel` 三栏（**线上 | 结果 | 我的**）；当前文件按需 `git_merge_blame` 显示两侧最近改的人（不是自动选边）。绿/蓝块网页可 auto，红块必须人点。按钮随档位：干净→落盘；`temp_local`→推送；`temp_remote` / 已推的临时枝→申请 MR；`already_merged`→无需操作。从矩阵进来：「完成冲突处理」只 `push: false` 记本地 `merge/…`，然后回矩阵。下拉不列 `merge/*` 当线上目标。
  - **矩阵**：多选 into / from，`git_merge_survey` 画格子。「去预演」或「开始逐条处理」切到单对记录选边（不推送）；回矩阵后冲突格若已有本地临时分支显示「已解决·本地」（merge-tree 结论仍是冲突，因为 from/into tip 没变）。矩阵统一处理顺序：先清剩余冲突，再 `git_push` 指定临时分支（不切换当前工作区），然后「申请 MR」。干净格源=from；已推临时分支源=临时分支。本会话开过的 PR/MR 记在 Pinia。SSE `repo-changed` 标矩阵可能过期。恰好 1 个 into 且 ≥2 个 from 时可 `git_merge_order`。不改工作区。不把多条 from 合成一条批量分支。
- **DiffViewer**（状态页工作区 / 提交抽屉共用）：`diff2html.parse` 拆文件；短文件默认展开，**变更行 ≥200** 或 `pnpm-lock.yaml` / `package-lock.json` / `yarn.lock` 默认收起，点整行文件头才 `html()`（结果缓存，再折再开不再算）。行号为表格单元格（非 absolute），左右各约 4.5em，与 `+/-` 同行着色。
- **操作日志**：Web / MCP / CLI 来源，按工具过滤，参数已脱敏。行高走全局 `--gc-line`，结果单行。
- **设置**（`/settings`，默认进 **MR 配置**；Git 操作用 `?tab=git`；正文规范用 `?tab=template`。高风险被拒引导 Git 操作 Tab；缺 Token 引导默认 MR Tab）：
  - **MR 配置**：默认远程为当前仓 `listRemotes()` 下拉（存 `mr.defaultRemote` 名），展示 URL 与识别出的平台；未识别时手动选 GitHub / GitLab。开单方式为可点卡片 **A 本机 CLI / B Token / C 浏览器页**（无 Insight 的下载 CLI，也无「自动」链式回退）；只展开当前方式。点选后按**当前仓库路径**写入 `mr.repoMethods`；该仓从未点过则默认 **C**。旧全局 `mr.method` 只作读盘兼容，不套到新仓。**Token / 平台按 remote 的 hostname**（`github.com/org/a.git` 与 `github.com/org/b.git` 共用一条 `hosts[]`）；开单方式仍按本机绝对路径，换仓不会自动带上 A/B。平台跟当前选中 remote：GitHub 只显示 gh / GitHub Token，GitLab 只显示 glab / GitLab Token。
  - **A**：一行状态 **未下载 / 未登录 / 已登录**。未下载时同行「去下载」（gh → `https://cli.github.com/`，glab → GitLab CLI releases）。探测合并 Windows 用户/系统 Path 与常见安装目录，不依赖当前进程 PATH，**不下载** CLI。已登录时用 `gh auth token` / `glab auth token` 走与 B 相同的 API 校验，摘要如 `有效 · login · 至 2027/08/19 00:00:00`（凭证不进 GET 响应）。
  - **B**：Token 绑定当前远程 hostname；创建 Token 链接与「自建 / API Base URL」同一行。输入框不回填明文，展示掩码（如 `ghp_••••abcd`）。保存前格式校验 + GitHub `GET /user` / GitLab `GET /user`（及 PAT self），失败 400 且不落盘。Node `fetch` 在校验与开 PR 前 `trustSystemCa()`，合并系统 CA（本机 HTTPS 代理把 `api.github.com` 指到 127.0.0.1 时，不再只报 `fetch failed`）。进 MR Tab 或「重新校验」时 `GET /api/settings?validateToken=1`。
  - **当前远程凭证**：只列出与当前 hostname 相同、且已识别为 GitHub/GitLab 的那一条，可整条删除。表单内无「清除已保存 Token」。其它实例的 Token 不在本页展示。
  - **正文规范**：导入 Markdown 转字段表，写入 `mr.template`。启用后网页弹层与 MCP `git_mr_create` 都必须按 `fields` 填，服务端渲染同一份 body。开单方式为浏览器页时，结果带回正文供复制，并提示改用 Token / CLI。
  - **Git 操作**：工具开关、审批、`dryRunDefault`、`allowedRepos`（空=不限制；非空则打开仓库时校验路径）。

- **实时同步**：`EventSource /api/events` 收 `repo-changed` 与 `log`，全局 revision +1，各视图自动刷新。
- **交互约定**：写操作一律先 `dryRun: true` 再弹确认框（展示将执行的 `git` 命令与风险），确认后才真实执行；高风险被拒时引导设置「Git 操作」Tab。

## 5. 总体架构

### 5.1 运行时架构

```
┌──────────────────────────────────────────────────────────┐
│     MCP 宿主 (Cursor / Claude 等聊天窗口)                │
│     stdio: git-cockpit mcp                               │
│     或 Streamable HTTP: http://localhost:3000/mcp        │
└────────────────────────┬─────────────────────────────────┘
                         │
┌────────────────────────▼─────────────────────────────────┐
│              mcp-server 进程（唯一后端）                    │
│  Runtime：config / SQLite / Permission / RepoManager     │
│  ┌────────────────────────────────────────────────────┐  │
│  │ executeCapability（core）安全链路                    │  │
│  │  权限 → zod → 解析仓库 → 高危备份 → handler → 审计 │  │
│  └────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────┐  │
│  │ GitService 实例池（每仓库一个，内部串行队列）        │  │
│  └────────────────────────────────────────────────────┘  │
│  Fastify：REST /api/*  +  SSE /api/events  +  静态前端   │
└────────────────────────┬─────────────────────────────────┘
                         │
┌────────────────────────▼─────────────────────────────────┐
│          Web 前端 (Vue 3 + Vite + Element Plus)          │
│  瘦客户端：只调 REST；写操作复用 /tools/:tool             │
└──────────────────────────────────────────────────────────┘
```

**关键约束**：已打开仓库上的 Git 写操作必须经过 `executeTool`（转调 core `executeCapability`）→ `GitService`，禁止前端或 MCP handler 直接 spawn git。**例外**：尚未成为仓库的 `git clone` 走 `clone.ts` + `jobs.ts` 的 `spawn('git', ['clone', '--progress', …])`（simple-git.clone 会整段缓冲，且没有当前仓队列可进）。stdio 模式是独立进程，与 `start` daemon **不共享**内存队列；多客户端共享队列需走 `git-cockpit start` 的 `/mcp`。

## 6. 核心实现逻辑

阅读代码时按这条链路走即可。

### 6.1 进程入口

1. `git-cockpit` → `cli-entry.ts` → `cli.main(argv)`。
2. 创建 **一次** `createRuntime({ dataDir })`：`trustSystemCa()`、读配置、打开 SQLite、装配 Permission / RepoStore / RepoManager / eventBus。`JobManager` 不在 Runtime 里，由 `createWebServer` 用同一 `db` 构造。
3. `mcp`：`startMcpStdio(runtime)`，进程挂在 stdio 上。
4. `start`：`createWebServer(runtime)` 监听端口；同进程挂 REST、SSE、`/mcp`、静态前端。SIGINT/SIGTERM 时 `server.close()` → `disposeRuntime`。

### 6.2 Runtime 与仓库池

`Runtime` 是进程内单例：一份配置、一个 DB、一个权限管理器、一个 `RepoManager`。

`RepoManager` 行为：
- 打开仓库时 `GitService.open`：`rev-parse --show-toplevel` 得到真实根目录，拒绝非 git 目录。
- 每个仓库根路径对应 **一个** `GitService`（懒创建），Web 的 `repoId` 与 MCP 的 `repoPath` 命中同一实例。
- 写成功后 GitService 发 `changed` → RepoManager 转到 `eventBus 'repo-changed'` → SSE 推前端。
- 已打开列表在 SQLite `opened_repos`（`pin_order` 工作台顺序；`last_opened_at` 最近打开）。`activate` 只刷新 `last_opened_at`。`PUT /api/repos/order` 保存拖拽顺序。

仓库解析优先级（`executeTool`）：`ctx.repoId` > `ctx.repoPath` > `args.repoPath` > 最近打开的一条。都没有则报 `NO_ACTIVE_REPO`。

### 6.3 executeTool 安全链路（最重要）

MCP 回调与 `POST /api/repos/:id/tools/:tool` **共用** `executeTool`，内部转调 core `executeCapability`。顺序固定：

```
1. 权限  PermissionManager.assertAllowed(tool)
2. 参数  def.schema.parse(rawArgs)（zod）
3. 仓库  host.resolveRepo → GitService（优先级 repoId > 上下文 repoPath > args.repoPath > 最近打开）
4. 备份  非 dry-run 且 risk===dangerous 且 backupOnDangerousOps
         → BackupManager.createBackup()（stash -u + backup/pre-op-{ts} 分支）
5. 执行  def.handler → GitService 方法（dryRun 时只返回 WritePreview）
6. 审计  AuditLogger.log（参数按 logging.redact 脱敏）
         失败分 result=error / denied；不向调用方抛异常，编码进 error 字段
```

`dryRun`：参数显式传入优先，否则用 `permissions.dryRunDefault`。

MCP 文本输出由 `formatResultForMcp` 拼接：失败前缀「需要审批」或「操作失败」；成功时附 dry-run 标记、备份信息、一行 `next: 工具名`，再 JSON。JSON 对象上附结构化 `next[]`（`{ tool, args }`），不把现有结果改成 `{ ok, summary, detail }` 信封。Web `POST /tools` 的 `result` **不附** `next`。

Web 前端 `useToolAction`：先 `runTool(..., { dryRun: true })` → `ConfirmDialog` 展示命令 → 再无 dryRun 执行。403 + `requiredApproval` 弹框引导 `/settings?tab=git`。缺 Token 引导 `/settings`（默认 MR 配置）。

### 6.4 GitService

- 所有命令 **数组传参、无 shell**，避免注入。日常读写走 `simple-git.raw`；`runAllowFail` 用 `spawn` 同时拿 stdout / stderr / exit code（merge-tree 冲突时 exit 1 仍是有效结果）。
- 内部 `enqueue` 串行；写前检查 `.git/index.lock`。
- `validateRepoRelativePath` 拒绝绝对路径与 `..` 越界；`validateRefName` 拒绝 `;|&`$`、空格及 git 非法 ref 字符。
- 错误转成 `GitOperationError`（带 code），并对「无提交 / 推送被拒 / 合并冲突」等给出中文提示。
- diff / 文件内容默认 2MB 截断。

**合并预演与落盘**（`gitService.ts` + `merge.ts`）：

- 方向写死：`into` = 合入目标（远程 / ours），`from` = 我的分支（theirs）。规范化后同名（如 `master` 与 `origin/master`）直接拒绝，请用户自行 push/pull。
- 预演只用 `git merge-tree --write-tree`（Git **≥ 2.38**，过低报 `GIT_TOO_OLD`，禁止退回工作区 `git merge`）。不改工作区、不切换 HEAD。
- `git_merge_rehearse` 在预演之上用临时目录跑 `merge-file --diff3`，返回冲突正文；仍不改仓库。网页用 `diff` 包把 ours/theirs/base 收成 hunk（`buildChangeHunks.ts`），三栏展示；落盘时把各文件 `resolvedContent` 交给 `git_apply_resolve`。
- `git_merge_blame` 对单个冲突文件两侧 tip 跑 `git blame --line-porcelain`（按 `diff -U0` 新侧行号），不改工作区；网页切文件时按需拉取。
- `git_apply_resolve` 在独立 worktree 里基于 `into` 建临时分支、merge `from`、写入已解决 `files`、可选 push；主工作区全程不切换。worktree 的创建/删除排进 **主仓库队列**。网页从矩阵进来时传 `push: false` + `keepLocal: true`（只留本地临时分支）；侧栏单对默认有远程则 push。矩阵上再对指定临时分支调 `git_push`（不 checkout）。
- 落盘成功时可拼浏览器创建页（GitHub compare / GitLab `merge_requests/new`）→ `createMrUrl`。
- **矩阵与合入顺序**（`survey.ts` / `chain.ts`）：`surveyMerges` 整批只 fetch 一次，格子只给路径；同名记 `same`，坏引用记 `error` 不拖垮整批。`suggestMergeOrder` 用 `commit-tree` 造游离 commit 往下推（作者写死 `git-cockpit@localhost`，不依赖仓库 user.email）；目标是 cleanPrefix，第一处冲突即停。贪心顺序对比传入顺序。不新建分支、不改工作区。
- **开 PR/MR**：`prepareMr` 用 `listRemotes()` / `listBranches()` 解析源/目标；远程名从 `into` 前缀或 origin/第一个 remote 推。`createPullOrMergeRequest` 用 `methodForRepo(mr, cwd)`（`mr.repoMethods` 按规范化仓库绝对路径）；该仓无记录则 **browser**。`git_mr_prepare` 带回 `method`。browser 只返回创建页 URL + 渲染正文（请复制粘贴），不写到远程；规范启用时提示改用 Token / CLI。Token / `apiBaseUrl` 按 **当前 remote 的 hostname** 查 `mr.hosts[]`。找不到 CLI **不下载**，返回官方安装地址。Token **禁止**作为工具入参。ssh → https 只走 `toHttpsRemoteUrl`。
- **fetch**：`fetch --prune --no-tags`；只更新远程跟踪引用，不改工作区、不合并。预演页可选先 fetch；状态页有 Fetch 按钮。`fetchQuiet` 仍给预演内部用，与工具 `git_fetch` 分开。
- **工作区 merge/rebase 收尾**（已开始的冲突，不是预演）：`getStatus().operation` 为 `merge` / `rebase`。`listWorkspaceConflicts()` 读 `ls-files -u` 的 `:1/:2/:3`。`mergeContinue` / `rebaseContinue` 可带 `files`：在同一队列里写入工作区并 `git add`，再用 `-c core.editor=true` + `GIT_EDITOR=true` 继续。`mergeAbort` / `rebaseAbort` 清掉进行中的操作。网页状态页告警条接这四个工具。**禁止**用 `git_apply_resolve` 收尾工作区冲突；**禁止**用预演工具冒充 continue。
- **分支图 lineage**：`getBranchGraph({ into, from })` 在 tip DAG 之外算 `merge-base` 与两侧 `rev-list --count`；无关历史则 `mergeBase` 为空。网页选 into/from 点「对比」后，有共同祖先时 G6 画三节点 Y 图（分叉点 / 线上 / 我的）。

### 6.5 权限模型

`TOOL_RISK_LEVELS` 将工具分为 `readonly` / `write` / `dangerous`。已注册 Capability 时 `PermissionManager` 读 registry 的 `risk`；未注册（core 单测）回退本表。

`evaluate(tool)`：
1. 在 `disabledTools` → 不允许；dangerous 时 `requiredApproval=true`（提示去设置开启）。
2. 在 `requireApprovalFor` → 不允许，`requiredApproval=true`。
3. 否则允许。

**没有运行时人工点批准的队列**：「审批」= 管理员从配置里去掉该工具的审批/禁用项。Web 设置页 `PUT /api/settings` 可更新 `permissions`、`git.allowedRepos` 与 `mr`（当前仓 `repoMethods`、`defaultRemote`、按 host upsert Token），当场写回 `config.json`。Token 在 snapshot / 审计中脱敏（非空才打 `[REDACTED]`，空串保持 `''`，避免设置页误以为还有 Token）；GET 不回明文，只暴露当前仓 `hosts[].tokenSet` / `tokenPreview`（掩码，且仅当前 hostname）、识别出的 host，以及可选的 `current.tokenStatus` / `cli.*.tokenStatus`（`validateToken=1` 或刚校验过的 PUT）。PUT 带新 Token 时先校验，无效不写入。

### 6.6 备份

高危真实执行前：
- 工作区不干净或有未跟踪 → `git stash push -u -m "git-cockpit backup {ts}"`；
- 尝试创建 `backup/pre-op-{timestamp}` 指向当前 HEAD（空仓库可能失败，忽略）。

`BackupManager.listBackups()` 列出 `backup/pre-op-*` 分支，以及说明匹配 `git-cockpit backup` 的 stash。不提供「reset --hard 一键回到备份」；网页「记录」卡片可检出备份分支、apply 备份 stash、按 reflog hash 检出（分离 HEAD）。`GET /api/repos/:id/backups`、`GET /api/repos/:id/reflog`；MCP：`git_backup_list`、`git_reflog`。

### 6.7 MCP 双传输

- **stdio**：一个 `McpServer` + `StdioServerTransport`，适合客户端拉起子进程。
- **Streamable HTTP**：`McpHttpHandler` 按 `mcp-session-id` 维护会话；无 session 则新建 transport。Fastify 已解析 body，必须把 `req.body` 传给 SDK，否则 initialize 无响应。
- 工具注册必须 `server.registerTool.bind(server)`，否则 SDK 丢失 `this` 导致握手挂起。Prompt / Resource 同样 `bind` 后注册。
- 服务端 `instructions`（与项目 `.cursor/rules/git-cockpit-mcp.mdc` 及 README「Agent 该怎么用」同口径）：先 `git_status`（`operation` 为 merge/rebase 时走工作区收尾）；写操作先 `dry_run=true`；高风险默认禁用；预演只用 merge-tree（`into`/`from`）；落盘用 `git_apply_resolve`；工作区冲突用 continue/abort；更新跟踪分支用 `git_fetch`；两分支分叉用 `git_branch_graph` 带 `into`/`from`。提交 / 预演落盘 / 工作区收尾 / 开 PR 用 Prompt；仓库列表与任务可读 Resource。

### 6.8 Web 服务要点

| 端点 | 作用 |
|------|------|
| `GET /api/health` | 探活；`version` 读 mcp-server `package.json`（与 MCP `MCP_SERVER_INFO`、OpenAPI `info.version` 同源）。网页侧栏与设置页展示该版本 |
| `GET`/`POST /open`/`DELETE /api/repos`、`PUT /api/repos/order` | 列表 / 打开 / 移除 / 拖拽顺序；`POST :id/activate` 刷新最近打开时间 |
| `GET /api/repos/overview` | 已打开仓脉搏，并行（并发 4），不经过 executeTool |
| `GET /api/repos/:id/{status,log,diff,show,branches,tags,remotes,graph,branch-graph,file,stashes,backups,reflog,workspace-conflicts}` | 只读，**不经过** executeTool（直接 GitService） |
| `GET /api/repos/:id/merge/{preview,rehearse,blame,survey,order}`、`GET .../mr/prepare` | 只读预演 / 开单解析，**不经过** executeTool、不进审计 |
| `POST /api/jobs`、`POST /api/jobs/clone`、`POST /api/jobs/:id/cancel`、`GET /api/jobs`、`GET /api/jobs/:id` | 通用后台任务（clone / survey / fetch）；`/clone` 兼容入口；详情含 `logs[]` |
| `POST /api/repos/:id/tools/:tool` | 写操作，走 executeTool |
| `GET /api/tools`、`GET/PUT /api/settings` | 工具表与权限；GET 可带 `?repoId=` 与 `validateToken=1`。`mr` 含该仓开单方式、`defaultRemote`、当前仓 remotes / host、当前域名凭证掩码、CLI 探测与可选校验摘要；PUT 可改 `permissions` 和/或该仓 method / `defaultRemote` / 按 host upsert 或删除 |
| `GET /api/logs` | 审计分页 |
| `GET /api/events` | SSE：`repo-changed`、`log`、`job-progress`，15s ping |
| `GET/POST /mcp` | MCP Streamable HTTP |
| `GET /docs` | Swagger UI；REST 摘要 + 各工具 `POST .../tools/:name`（由 TOOL_DEFS 生成）。通用 `POST .../tools/:tool` 与 `/mcp` 不进文档 |
| `/` | 静态 `web/dist`；SPA fallback（hash 路由；跳过 `/api` `/mcp` `/docs`） |

`JobManager` 用 `JobStore(runtime.db)`：启动 `restore()` 把库里仍是 `running` 的标成 `error`（「服务重启，任务中断」）；进行中约 200ms 落盘，结束强制写。SSE `job-progress` 约 200ms 节流，漏掉的 `chunk` 攒到下次；结束事件带 `ok`/`error` 但不保证完整日志，前端再 `GET /api/jobs/:id`。保留最近约 30 条。

`resolveWebDist` 按优先级找 `index.html`：源码布局 `packages/web/dist` → 发布布局 `dist/web` → 若干兼容路径。开发时 Vite `:5173` 代理 `/api` 与 `/mcp` 到 daemon。

只读 REST 与 MCP 只读工具数据同源（同一 GitService），但 REST 只读不写审计；打开仓库、activate、经 tools 的调用会记日志。

### 6.9 前端状态同步

1. `App.vue` 启动：health → 拉仓库列表 → `branches.load()` → 订 SSE。换仓库或 revision 变化时再拉分支列表（请求去重）。
2. SSE 到达 → `useRevision().bump()` → Status / Logs `watch(revision)` 刷新；合并页若已有调查结果则标「矩阵可能过期」（不自动重跑）。Agent / MCP 不订 `/api/events`，收不到这些事件。
3. 当前仓库：`localStorage git-cockpit:currentRepoId` 优先，否则卡片顺序第一项。
4. 分支数据：`useBranchesStore` 一份扁平列表；状态页工作区左树、合并页树选、提交面板「指定分支」共用，页面只做 scope 过滤（本地 / 远程 / 全部）。合并页单对与矩阵共用 `useMergeSessionStore`，切模式不丢调查结果与冲突队列。
5. 后台任务：`useJobsStore` 订 SSE `job-progress`，`chunk` 按 `\n`/`\r` 拆行追加；收到 `ok`/`error` 再拉详情并 Notification。侧栏「任务」显示进行中数量。克隆成功后打开目标路径加入仓库列表。任务页左列表右日志，无抽屉；`?id=` 与左栏选中同步。

## 7. 技术选型

| 模块 | 实际方案 | 说明 |
|------|----------|------|
| 运行时 | Node.js ≥ 22.5 + TypeScript | `node:sqlite` 要求；根 engines 为 ≥22 |
| MCP SDK | `@modelcontextprotocol/sdk` | stdio + Streamable HTTP |
| Git | simple-git + `run` / `runAllowFail`；克隆例外用 `child_process.spawn` | 参数数组；预演需本机 Git ≥ 2.38；`git clone --progress` 见 5.1 |
| Web 框架 | Fastify 5 | REST + 静态 + 劫持 SSE/MCP |
| 实时 | **SSE**（`/api/events`） | `repo-changed`、`log`、`job-progress`；未用 Socket.IO |
| 前端 | Vue 3 + Vite 6 + Pinia + Vue Router（hash）+ `@antv/g6` | 暗色 Element Plus；状态页分支图 G6 dagre |
| Diff | diff2html（状态页工作区 / 提交抽屉）；`diff` 包（合并三栏 hunk） | 失败回退纯文本；冲突页无语法高亮 |
| 数据库 | **node:sqlite**（非 better-sqlite3） | `~/.git-cockpit/git-cockpit.db`，WAL |

| 发布 | GitHub Actions + `pnpm publish` | 必须用 pnpm 才能改写 `workspace:` |

## 8. 风险把控

### 8.1 风险矩阵

| 风险类别 | 等级 | 应对（已落地部分） |
|---------|------|-------------------|
| Git 误操作丢数据 | 高 | 高风险默认禁用+审批；执行前 stash+备份分支；dry-run+二次确认 |
| 命令注入 | 高 | simple-git 数组传参；路径/ref 校验 |
| 宿主 Agent 误调危险操作 | 中高 | 默认禁用；工具 description 标明风险；instructions 要求先 dry_run |
| 预演误改工作区 | 高 | 只用 merge-tree；落盘只用独立 worktree |
| 并发损坏索引 | 中 | 每仓库串行队列；写前检查 index.lock；同 daemon 内 Web/MCP 共用实例 |
| 敏感信息泄露 | 中高 | 审计脱敏（password/token/authorization）；设置快照同样脱敏 |
| 远程误推送 | 中 | 普通 push 非强制；force 用 `--force-with-lease` 且默认禁用 |
| 大仓库性能 | 中 | log maxCount 上限；diff 2MB 截断；历史条数前端可选 |
| stdio 破坏唯一后端 | 中 | 文档约定：多客户端共享请用 `start` + `/mcp` |

未落地的部署与安全项见本文 §13，此处不列规划清单。

### 8.2 安全机制摘要

- 三级工具 + 配置开关，无独立审批工单系统。
- 写操作 dry-run 返回 `{ dryRun, command, args, affectedFiles, risk, note }`。
- 高危自动备份见 6.6。
- 日志：时间、source、工具、仓库路径、脱敏参数、结果、耗时、是否 dry-run。

## 9. 数据与配置

数据目录默认 `~/.git-cockpit`（`GIT_COCKPIT_DATA_DIR` / `storage.dataDir`）：

| 文件 | 内容 |
|------|------|
| `config.json` | 服务端口、git 并发、权限、日志脱敏词、`mr.repoMethods`（按仓库路径的开单方式）、`mr.hosts[]`（按 hostname 的 Token） |
| `git-cockpit.db` | `operations` 审计表、`opened_repos` 仓库列表、`jobs` 后台任务（clone / survey / fetch） |

配置合并：`DEFAULT_CONFIG` ← 文件 ← 构造期 overrides，再 `normalizeMrConfig`（旧 `githubToken`/`gitlabToken` 迁到 `hosts`；旧 `method: auto` 迁成 `browser`）。损坏的 JSON 不阻断启动。`PUT /api/settings` 允许改 `permissions`，以及按当前仓写 `repoMethods`、改 `defaultRemote`、按 host upsert 或删除。snapshot 中非空 Token 显示为 `[REDACTED]`，已清除的空 Token 保持 `''`。

默认权限（`packages/core/src/types.ts`）：

```json
{
  "server": { "port": 3000, "host": "localhost" },
  "storage": { "dataDir": "~/.git-cockpit" },
  "git": {
    "maxConcurrentOperations": 1,
    "backupOnDangerousOps": true,
    "allowedRepos": []
  },
  "permissions": {
    "disabledTools": [
      "git_reset_hard", "git_clean", "git_push_force",
      "git_branch_delete_force", "git_rebase"
    ],
    "requireApprovalFor": [
      "git_reset_hard", "git_clean", "git_push_force",
      "git_branch_delete_force", "git_rebase"
    ],
    "dryRunDefault": false
  },
  "logging": {
    "level": "info",
    "redact": ["password", "token", "authorization"]
  },
  "mr": {
    "method": "browser",
    "defaultRemote": "origin",
    "hosts": [],
    "repoMethods": {}
  }
}
```

`allowedRepos` 为空不限制；非空时打开仓库（Web / MCP `repoPath`）必须等于名单中某条路径，或位于其目录下，否则 `REPO_NOT_ALLOWED`。

`git.maxConcurrentOperations` **目前不生效**：每仓 GitService 内部队列永远串行（保护 index）；跨仓本就可并行。设置页不暴露此字段。

### 11.2 本地使用

```bash
npm install -g @shaohui_jin/git-cockpit-mcp-server
git-cockpit start
# Web:  http://localhost:3000
# MCP:  http://localhost:3000/mcp
```

- stdio：`{ "command": "git-cockpit", "args": ["mcp"] }`
- HTTP：`{ "url": "http://localhost:3000/mcp" }`

开发（仓库根目录）：

pnpm install && pnpm build

# API 文档:  http://localhost:3000/docs
```

`prestart` 会先构建 core 与 mcp-server；`start` 并行拉起 daemon 与 Vite。亦可：

node packages/mcp-server/dist/cli-entry.js start
# 另开终端：pnpm --filter @shaohui_jin/git-cockpit-web dev
```

### 11.3 npm 发布（与代码一致）

发布自动化在 **单个** `.github/workflows/release.yml`（两个 job，`release-mcp-server` `needs: release-core`），**不是**历史上的两个独立 workflow。

| 包 | tag | 判据 |
|----|-----|------|
| core | `core-v{version}` | 远程无此 tag 才 publish |
| mcp-server | `mcp-server-v{version}` | 同上 |

设计要点：
- **tag 在 publish 成功之后才推送**，表示「已发布」而非「试过了」；失败可原样重跑，不浪费版本号。
- 必须 `pnpm publish`：只有 pnpm 会把 `workspace:^` 改成真实 semver。
- mcp-server job 会先 **build core**（全新 checkout 无 `dist`），再 build web，再 publish mcp-server（`prepublishOnly` 复制 `dist/web`）。
- 因 job 顺序保证 core 先发，**不再**在 mcp-server 内轮询 `npm view`。
- 触发：push `master`/`main` 或 `workflow_dispatch`。Secret：`NPM_TOKEN`。
- core `0.x` 的 caret（如 `^0.1.0`）只覆盖 0.1.x；core 升 minor 时需同步 mcp-server 依赖范围。

core 构建后 `postbuild.mjs` 把 esbuild 剥掉的 `from "sqlite"` 改回 `from "node:sqlite"`。

失败重试、本地 dry-run 核对 tarball、镜像延迟等细节见 [release.md](./release.md)。

当前按本地单用户 daemon 设计，默认 `host=localhost`。远程多租户不在已实现范围内。

## 12. 注意事项与开发关键点

1. **唯一后端**：日常多人/多客户端应使用 `start` + HTTP MCP，避免多个 stdio 进程各写同一仓库。
2. **写操作收口**：新工具写进 `core/capabilities/git/*.ts` + GitService 方法，不要只写在 mcp-server，也不要在 Web 路由里直接调 git。
3. **只读 REST 无审计**：若需要「谁看过 diff」审计，应改为走 executeTool 或补日志。
4. **打包**：core 必须 external `node:sqlite` 并跑 postbuild；mcp-server 必须 shebang（`cli-entry.js`），且 core/SDK/fastify/zod 不 bundle。
5. **静态资源**：发布包靠 `dist/web`；源码开发靠 `packages/web/dist` 或 Vite 代理。
6. **Windows**：bin 无扩展名 + shebang，Git for Windows 才能找到 `git cockpit`；纯 `.cmd` 不会被 git 的 PATH 查找命中。
7. **体验**：无仓库时禁用写按钮；远程操作失败用 GitOperationError 友好文案（如「请先拉取」）。

## 15. 总结

Git Cockpit 把 **MCP 工具、Web API、CLI** 收束到同一套 `Runtime` + `executeTool` + `GitService`。宿主聊天窗口里的 Agent 与网页点按钮走同一套权限、预览、备份和审计。侧栏干活（已配模型 Key 时聊天置顶，否则在合并后）与系统（任务 / 操作日志 / 设置）分开；提交在状态页第三档，没有独立历史页。合并预演不碰工作区；多分支可矩阵扫描并建议合入顺序；从矩阵选边只记本地临时分支，回矩阵再推送、开 MR；侧栏进单对仍可落盘并推送。落盘走独立 worktree。工作区已经冲突时用 continue/abort，不用 `git_apply_resolve`。状态页可看 tip DAG 与两分支 lineage、按路径树看更改、做日常写操作并回看备份/reflog；后台任务左右分栏看日志并可取消克隆。Insight 能力迁入已完成（下架不做）。本产品不内置对话模型。发版以 tag-after-publish 的单 workflow 为准。尚未落地事实见本文 §13。
