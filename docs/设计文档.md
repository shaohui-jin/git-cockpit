## 1. 项目概述

**项目名称**：Git Cockpit（展示名；npm 包：`@shaohui_jin/git-cockpit-mcp-server`，CLI：`git-cockpit`，完整命名规范见 11.1 节）  
**项目定位**：基于 MCP 的 Git 可视化操作工具：Web 界面 + 供外部 Agent 调用的 MCP 工具，支持多仓库与安全的 Git 操作。本产品 **不内置聊天或选边模型**（无 LLM 配置）。  
**当前形态**：一个 npm 包三种入口——**MCP Server**（宿主在聊天窗口里调工具）、**Web**、**CLI**（`git-cockpit start` / `mcp`）。**不做** Cursor/VS Code 扩展。

**核心价值**：
- **工具给宿主用**：Cursor、Claude 等通过 MCP 调用 `git_status` 等（脑子在宿主，不在 Cockpit）。
- **可视化交互**：浏览器内完成暂存、提交、分支、stash、拉取/推送等。
- **安全可控**：高风险默认禁用；写操作 dry-run 预览 → 确认 → 执行；高危自动备份；审计日志。
- **唯一后端**：Web 与 MCP 共用 Runtime / GitService，队列与锁全局生效。

## 2. 目标用户与使用场景

### 2.1 目标用户
- 前端/全栈开发者，希望在聊天窗口里用 Agent 辅助 Git（通过 MCP 工具）。
- 不熟悉 Git 命令行的开发者，需要可视化界面。
- 团队协作者，需要审查历史、查看差异。
- 希望用 MCP 把 Git 接进 Agent 工作流的用户（在 **编辑器聊天窗口** 里操作，不是打开 Cockpit 内置对话）。

### 2.2 典型场景
1. **宿主辅助提交**：用户在聊天窗口说「看看当前改动并提交」，宿主模型调用 `git_status`、`git_diff`，再调用 `git_add` 和 `git_commit`。
2. **历史分析**：宿主调用 `git_log` / `git_show`，在对话里回答关于代码变更的问题。
3. **可视化手动操作**：用户在 Web 状态页勾选文件、暂存、提交、推送；操作前弹出 dry-run 预览确认框。
4. **选择性 stash**：勾选部分文件 stash（对应 IDE Shelve），可 apply / pop / drop，并查看 stash diff。
5. **多仓库切换**：打开多个本地仓库，按最近打开排序，状态/历史/合并视图跟随当前仓库刷新。
6. **权限治理**：在设置页开关高风险工具、配置审批名单；被拒操作会引导前往设置。
7. **合并预演、矩阵、选边与落盘**：网页选 `into`（合入目标 / ours）与 `from`（我的分支 / theirs），`merge-tree` 预演不改工作区；多分支用矩阵扫描、可建议合入顺序。从矩阵进单对：三栏选边后「完成冲突处理」只写入本地 `merge/…`（`push: false`），再回矩阵看「已解决·本地」，再在矩阵上推送该临时分支、申请 MR。从侧栏直接进单对仍可「落盘并推送」。亦可在宿主聊天窗口调 `git_merge_rehearse` / `git_merge_survey` / `git_merge_order` → `git_apply_resolve`。开 PR/MR 走设置里的 Token / 本机 gh·glab / 浏览器页。不把多条 from 合成一条批量分支。

## 4. 功能范围

### 4.1 MCP 工具集（供宿主 Agent 与 Web 共用）

工具定义在 `packages/mcp-server/src/tools/index.ts`，参数 Schema 在 `schemas.ts`（zod）。每个工具均支持可选 `repoPath`（缺省为最近打开仓库）与写操作 `dryRun`。

#### 只读工具（默认开放）

| 工具名称 | 功能描述 |
|---------|---------|
| `git_status` | 工作区状态：分支、已暂存/未暂存/未跟踪、冲突、领先/落后上游 |
| `git_log` | 提交历史（分页、作者/路径/范围/`--all`） |
| `git_diff` | 工作区/暂存区/提交范围差异；大 patch 默认截断 2MB |
| `git_show` | 某次提交元信息 + 相对父提交的 diff |
| `git_branch_list` | 本地/远程分支；本地带 upstream 与 ahead/behind |
| `git_tag_list` | 标签（按创建时间倒序） |
| `git_remote_list` | 远程名称与 fetch/push URL |
| `git_file_content` | 指定提交中文件内容（大文件截断 2MB） |
| `git_graph` | 分支拓扑数据（提交、父节点、refs、HEAD），供可视化 |
| `git_stash_list` | 全部 stash 记录（`stash@{n}` / 说明 / 时间） |
| `git_stash_show` | 查看某条 stash 的 diff（不改仓库） |
| `git_merge_preview` | `merge-tree` 预演把 `from` 合入 `into`（不改工作区）；返回是否干净及冲突文件列表。Git ≥ 2.38 |
| `git_merge_rehearse` | 预演 + 冲突文件 diff3 正文（ours/theirs/base）。网页三栏或宿主选边后把 `files` 交给 `git_apply_resolve` |
| `git_mr_prepare` | 只读：解析开 PR/MR 的源/目标、浏览器创建页、本机 gh/glab 是否在 PATH（找不到则带官方安装地址）、可选审核人列表。不把 Token 当参数 |
| `git_merge_survey` | 批量预演：`intos × froms` 每对 `merge-tree` 一次，整批只 fetch 一次；只返回 outcome、冲突路径、已有 `merge/*` 临时分支。不生成正文、不带格子颜色。单格失败不影响其余格 |
| `git_merge_order` | 建议多个 from 合入同一 into 的顺序：对象库内结果树 + `commit-tree` 游离 commit，不改工作区；返回建议顺序、cleanPrefix、从哪步开始要人工 |

#### 写操作工具（默认开放，需预览/确认）

| 工具名称 | 功能描述 |
|---------|---------|
| `git_add` | 暂存指定路径；空则暂存全部 |
| `git_unstage` | 取消暂存（`git reset HEAD --`） |
| `git_commit` | 创建提交；可限定 paths、`allowEmpty` |
| `git_checkout` | 切换分支；本地更改会被覆盖时拒绝 |
| `git_branch_create` | 创建分支（可选 startPoint） |
| `git_branch_delete` | 安全删除（`-d`，未合并则拒绝） |
| `git_merge` | 普通合并；冲突时返回明确错误 |
| `git_pull` | 非强制拉取 |
| `git_push` | 非强制推送；可指定 `remote` / `branch`（矩阵推送本地 `merge/…` 时不切换当前工作区）。被拒时提示先 pull |
| `git_tag_create` | 轻量/附注标签 |
| `git_stash` | stash；可 `-u`、可 `paths` 选择性暂存 |
| `git_stash_apply` | 应用 stash（保留记录） |
| `git_stash_drop` | 删除 stash 记录 |
| `git_stash_pop` | 恢复并删除该条 stash |
| `git_apply_resolve` | 独立 worktree 落盘：基于 `into` 建临时分支、merge `from`、写入已解决 `files`、可选 push。主工作区不切换。矩阵流程传 `push: false` + `keepLocal: true` 只留本地 |
| `git_mr_create` | 按设置 MR 配置开 PR/MR：`token`、`cli`、`browser`。GitLab 审核人用户名会解析成数字 id。Token **不进**工具参数。找不到 gh/glab 时结果/错误含官方安装地址 |

#### 高风险工具（默认禁用 + 需审批，执行前自动备份）

| 工具名称 | 功能描述 |
|---------|---------|
| `git_reset_hard` | `reset --hard` |
| `git_clean` | `clean -df` |
| `git_push_force` | `--force-with-lease`（非裸 `--force`） |
| `git_branch_delete_force` | `branch -D` |
| `git_rebase` | 变基 |

默认配置：上述 5 个同时出现在 `disabledTools` 与 `requireApprovalFor`。要真正执行，必须在设置中**同时移出禁用名单与审批名单**。

Web 写操作走同一套工具，入口为 `POST /api/repos/:id/tools/:tool`。状态页已接的按钮：add / unstage / commit / checkout / branch_create / pull / push / stash 全家 / reset_hard / clean。合并页：预演走 `git_merge_preview` / `git_merge_rehearse`（可先 fetch）；矩阵进单对后 `git_apply_resolve`（`push: false`）；矩阵上再 `git_push` 指定临时分支、`git_mr_create`。侧栏单对可落盘并推送。工作区 `git_merge`、tag、rebase、force push、删分支目前仅 MCP 可调（勿与 merge-tree 预演混用）。

### 4.2 Web 可视化界面（已实现）

- **仓库管理**：打开本地路径、按路径树展示最近列表、激活/移除；当前仓库记入 `localStorage`。
- **状态视图**：未暂存 / 已暂存 / 未跟踪 / 全部；勾选后暂存或选择性 stash；文件 diff 抽屉（diff2html）；分支树（本地 + 远程分组，↑↓ 同步信息，数据来自分支 store）；stash 列表（查看 diff / apply / pop / drop）；提交、建分支、拉取、推送、硬重置、清理未跟踪。
- **合并视图**（`/merge`，侧栏一项；`/matrix` 重定向到 `?mode=matrix`）：页内切换 **单对预演 | 矩阵**，状态在 `useMergeSessionStore`（内存，换仓清空，不写 SQLite）。
  - **单对**：`BranchTreeSelect` 选合入目标 `into`（线上 / ours，远程组优先）与我的分支 `from`（theirs）；可选非交互 fetch；预演得到干净 / 冲突 / 无关历史。有冲突时 `ConflictResolvePanel` 三栏（**线上 | 结果 | 我的**）。从侧栏直接进单对：选完后可「落盘并推送」。从矩阵进来：按钮为「完成冲突处理」，`git_apply_resolve` 且 `push: false`，只把选边提交到本地 `merge/…` 临时分支（主区不切换），然后回矩阵；不在这一步推送或开 MR。
  - **矩阵**：多选 into / from，`git_merge_survey` 画格子。「去预演」或「开始逐条处理」切到单对记录选边（不推送）；回矩阵后冲突格若已有本地临时分支显示「已解决·本地」（merge-tree 结论仍是冲突，因为 from/into tip 没变）。矩阵统一处理顺序：先清剩余冲突，再 `git_push` 指定临时分支（不切换当前工作区），然后「申请 MR」。干净格源=from；已推临时分支源=临时分支。本会话开过的 PR/MR 记在 Pinia。SSE `repo-changed` 标矩阵可能过期。恰好 1 个 into 且 ≥2 个 from 时可 `git_merge_order`。不改工作区。不把多条 from 合成一条批量分支。
- **历史视图**：HEAD / 全部分支 / 指定分支（同样树选，可含远程）；路径过滤、条数限制；点击提交打开 diff 抽屉。
- **操作日志**：Web / MCP / CLI 来源，按工具过滤，参数已脱敏。
- **设置**（`/settings`，默认进 **MR 配置**；Git 操作用 `?tab=git`。高风险被拒引导 Git 操作 Tab；缺 Token 引导默认 MR Tab）：
  - **MR 配置**：默认远程为当前仓 `listRemotes()` 下拉（存 `mr.defaultRemote` 名），展示 URL 与识别出的平台；未识别时手动选 GitHub / GitLab。开单方式为可点卡片 **A 本机 CLI / B Token / C 浏览器页**（无 Insight 的下载 CLI，也无「自动」链式回退）；只展开当前方式。点选后按**当前仓库路径**写入 `mr.repoMethods`；该仓从未点过则默认 **C**。旧全局 `mr.method` 只作读盘兼容，不套到新仓。平台跟当前选中 remote：GitHub 只显示 gh / GitHub Token，GitLab 只显示 glab / GitLab Token。
  - **A**：一行状态 **未下载 / 未登录 / 已登录**。未下载时同行「去下载」（gh → `https://cli.github.com/`，glab → GitLab CLI releases）。探测合并 Windows 用户/系统 Path 与常见安装目录，不依赖当前进程 PATH，**不下载** CLI。已登录时用 `gh auth token` / `glab auth token` 走与 B 相同的 API 校验，摘要如 `有效 · login · 至 2027/08/19 00:00:00`（凭证不进 GET 响应）。
  - **B**：Token 绑定当前远程 hostname；创建 Token 链接与「自建 / API Base URL」同一行。输入框不回填明文，展示掩码（如 `ghp_••••abcd`）。保存前格式校验 + GitHub `GET /user` / GitLab `GET /user`（及 PAT self），失败 400 且不落盘。进 MR Tab 或「重新校验」时 `GET /api/settings?validateToken=1`。
  - **当前远程凭证**：只列出与当前 hostname 相同、且已识别为 GitHub/GitLab 的那一条，可整条删除。表单内无「清除已保存 Token」。其它实例的 Token 不在本页展示。
  - **Git 操作**：工具开关、审批、`dryRunDefault`。

- **实时同步**：`EventSource /api/events` 收 `repo-changed` 与 `log`，全局 revision +1，各视图自动刷新。
- **交互约定**：写操作一律先 `dryRun: true` 再弹确认框（展示将执行的 `git` 命令与风险），确认后才真实执行；高风险被拒时引导设置「Git 操作」Tab。

### 4.3 CLI

```
git-cockpit start     # 常驻 daemon：Web + MCP Streamable HTTP，默认 :3000
git-cockpit mcp       # stdio MCP（供客户端拉起独立进程）
git-cockpit version
git-cockpit help
```

bin 名为 `git-cockpit`，因此 `git cockpit start` 与 `git-cockpit start` 等价（Git 外部子命令机制）。

环境变量：`GIT_COCKPIT_DATA_DIR`（默认 `~/.git-cockpit`）、`GIT_COCKPIT_PORT`、`GIT_COCKPIT_HOST`。

## 5. 总体架构

### 5.1 运行时架构

```
┌──────────────────────────────────────────────────────────┐
│     MCP 宿主 (Cursor / Claude 等聊天窗口)                │
│     stdio: git-cockpit mcp                               │
│     或 Streamable HTTP: http://localhost:3000/mcp        │
└────────────────────────┬─────────────────────────────────┘
                         │
┌────────────────────────▼─────────────────────────────────┐
│              mcp-server 进程（唯一后端）                    │
│  Runtime：config / SQLite / Permission / RepoManager     │
│  ┌────────────────────────────────────────────────────┐  │
│  │ executeTool 安全链路                               │  │
│  │  权限 → zod → 解析仓库 → 高危备份 → handler → 审计 │  │
│  └────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────┐  │
│  │ GitService 实例池（每仓库一个，内部串行队列）        │  │
│  └────────────────────────────────────────────────────┘  │
│  Fastify：REST /api/*  +  SSE /api/events  +  静态前端   │
└────────────────────────┬─────────────────────────────────┘
                         │
┌────────────────────────▼─────────────────────────────────┐
│          Web 前端 (Vue 3 + Vite + Element Plus)          │
│  瘦客户端：只调 REST；写操作复用 /tools/:tool             │
└──────────────────────────────────────────────────────────┘
```

**关键约束**：所有 Git 写操作必须经过 `executeTool` → `GitService`，禁止前端或 MCP handler 直接 spawn git。stdio 模式是独立进程，与 `start` daemon **不共享**内存队列；多客户端共享队列需走 `git-cockpit start` 的 `/mcp`。

## 6. 核心实现逻辑

阅读代码时按这条链路走即可。

### 6.1 进程入口

1. `git-cockpit` → `cli-entry.ts` → `cli.main(argv)`。
2. 创建 **一次** `createRuntime({ dataDir })`：读配置、打开 SQLite、装配 Permission / RepoStore / RepoManager / eventBus。
3. `mcp`：`startMcpStdio(runtime)`，进程挂在 stdio 上。
4. `start`：`createWebServer(runtime)` 监听端口；同进程挂 REST、SSE、`/mcp`、静态前端。SIGINT/SIGTERM 时 `server.close()` → `disposeRuntime`。

### 6.2 Runtime 与仓库池

`Runtime` 是进程内单例：一份配置、一个 DB、一个权限管理器、一个 `RepoManager`。

`RepoManager` 行为：
- 打开仓库时 `GitService.open`：`rev-parse --show-toplevel` 得到真实根目录，拒绝非 git 目录。
- 每个仓库根路径对应 **一个** `GitService`（懒创建），Web 的 `repoId` 与 MCP 的 `repoPath` 命中同一实例。
- 写成功后 GitService 发 `changed` → RepoManager 转到 `eventBus 'repo-changed'` → SSE 推前端。
- 最近打开列表在 SQLite `opened_repos`；`activate` 只刷新 `last_opened_at`。

仓库解析优先级（`executeTool`）：`ctx.repoId` > `ctx.repoPath` > `args.repoPath` > 最近打开的一条。都没有则报 `NO_ACTIVE_REPO`。

### 6.3 executeTool 安全链路（最重要）

MCP 回调与 `POST /api/repos/:id/tools/:tool` **共用** `executeTool`。顺序固定：

```
1. 权限  PermissionManager.assertAllowed(tool)
2. 参数  def.schema.parse(rawArgs)（zod）
3. 仓库  resolveRepo → GitService
4. 备份  非 dry-run 且 risk===dangerous 且 backupOnDangerousOps
         → BackupManager.createBackup()（stash -u + backup/pre-op-{ts} 分支）
5. 执行  def.handler → GitService 方法（dryRun 时只返回 WritePreview）
6. 审计  AuditLogger.log（参数按 logging.redact 脱敏）
         失败分 result=error / denied；不向调用方抛异常，编码进 error 字段
```

`dryRun`：参数显式传入优先，否则用 `permissions.dryRunDefault`。

MCP 文本输出由 `formatResultForMcp` 拼接：失败前缀「需要审批」或「操作失败」；成功时附 dry-run 标记、备份信息、JSON/字符串结果。

Web 前端 `useToolAction`：先 `runTool(..., { dryRun: true })` → `ConfirmDialog` 展示命令 → 再无 dryRun 执行。403 + `requiredApproval` 弹框引导 `/settings?tab=git`。缺 Token 引导 `/settings`（默认 MR 配置）。

### 6.4 GitService

- 所有命令 **数组传参、无 shell**，避免注入。日常读写走 `simple-git.raw`；`runAllowFail` 用 `spawn` 同时拿 stdout / stderr / exit code（merge-tree 冲突时 exit 1 仍是有效结果）。
- 内部 `enqueue` 串行；写前检查 `.git/index.lock`。
- `validateRepoRelativePath` 拒绝绝对路径与 `..` 越界；`validateRefName` 拒绝 `;|&`$`、空格及 git 非法 ref 字符。
- 错误转成 `GitOperationError`（带 code），并对「无提交 / 推送被拒 / 合并冲突」等给出中文提示。
- diff / 文件内容默认 2MB 截断。

**合并预演与落盘**（`gitService.ts` + `merge.ts`）：

- 方向写死：`into` = 合入目标（远程 / ours），`from` = 我的分支（theirs）。规范化后同名（如 `master` 与 `origin/master`）直接拒绝，请用户自行 push/pull。
- 预演只用 `git merge-tree --write-tree`（Git **≥ 2.38**，过低报 `GIT_TOO_OLD`，禁止退回工作区 `git merge`）。不改工作区、不切换 HEAD。
- `git_merge_rehearse` 在预演之上用临时目录跑 `merge-file --diff3`，返回冲突正文；仍不改仓库。网页用 `diff` 包把 ours/theirs/base 收成 hunk（`buildChangeHunks.ts`），三栏展示；落盘时把各文件 `resolvedContent` 交给 `git_apply_resolve`。
- `git_apply_resolve` 在独立 worktree 里基于 `into` 建临时分支、merge `from`、写入已解决 `files`、可选 push；主工作区全程不切换。worktree 的创建/删除排进 **主仓库队列**。网页从矩阵进来时传 `push: false` + `keepLocal: true`（只留本地临时分支）；侧栏单对默认有远程则 push。矩阵上再对指定临时分支调 `git_push`（不 checkout）。
- 落盘成功时可拼浏览器创建页（GitHub compare / GitLab `merge_requests/new`）→ `createMrUrl`。
- **矩阵与合入顺序**（`survey.ts` / `chain.ts`）：`surveyMerges` 整批只 fetch 一次，格子只给路径；同名记 `same`，坏引用记 `error` 不拖垮整批。`suggestMergeOrder` 用 `commit-tree` 造游离 commit 往下推（作者写死 `git-cockpit@localhost`，不依赖仓库 user.email）；目标是 cleanPrefix，第一处冲突即停。贪心顺序对比传入顺序。不新建分支、不改工作区。
- **开 PR/MR**：`prepareMr` 用 `listRemotes()` / `listBranches()` 解析源/目标；远程名从 `into` 前缀或 origin/第一个 remote 推。`createPullOrMergeRequest` 用 `methodForRepo(mr, cwd)`（`mr.repoMethods` 按规范化仓库绝对路径）；该仓无记录则 **browser**。Token / `apiBaseUrl` 按 **当前 remote 的 hostname** 查 `mr.hosts[]`。找不到 CLI **不下载**，返回官方安装地址。Token **禁止**作为工具入参。ssh → https 只走 `toHttpsRemoteUrl`。

### 6.5 权限模型

`TOOL_RISK_LEVELS` 将工具分为 `readonly` / `write` / `dangerous`。

`evaluate(tool)`：
1. 在 `disabledTools` → 不允许；dangerous 时 `requiredApproval=true`（提示去设置开启）。
2. 在 `requireApprovalFor` → 不允许，`requiredApproval=true`。
3. 否则允许。

**没有运行时人工点批准的队列**：「审批」= 管理员从配置里去掉该工具的审批/禁用项。Web 设置页 `PUT /api/settings` 可更新 `permissions` 与 `mr`（当前仓 `repoMethods`、`defaultRemote`、按 host upsert Token），当场写回 `config.json`。Token 在 snapshot / 审计中脱敏；GET 不回明文，只暴露当前仓 `hosts[].tokenSet` / `tokenPreview`（掩码，且仅当前 hostname）、识别出的 host，以及可选的 `current.tokenStatus` / `cli.*.tokenStatus`（`validateToken=1` 或刚校验过的 PUT）。PUT 带新 Token 时先校验，无效不写入。

### 6.6 备份

高危真实执行前：
- 工作区不干净或有未跟踪 → `git stash push -u -m "git-cockpit backup {ts}"`；
- 尝试创建 `backup/pre-op-{timestamp}` 指向当前 HEAD（空仓库可能失败，忽略）。

不提供一键「从备份恢复」UI；恢复需用户自行 checkout/stash pop。`listBackups` 存在但未接到前端。

### 6.7 MCP 双传输

- **stdio**：一个 `McpServer` + `StdioServerTransport`，适合客户端拉起子进程。
- **Streamable HTTP**：`McpHttpHandler` 按 `mcp-session-id` 维护会话；无 session 则新建 transport。Fastify 已解析 body，必须把 `req.body` 传给 SDK，否则 initialize 无响应。
- 工具注册必须 `server.registerTool.bind(server)`，否则 SDK 丢失 `this` 导致握手挂起。
- 服务端 `instructions` 要求：先 `git_status`；写操作先 `dry_run=true`；高风险默认禁用。

### 6.8 Web 服务要点

| 端点 | 作用 |
|------|------|
| `GET /api/health` | 探活 |
| `GET/POST/DELETE /api/repos` | 列表 / 打开 / 移除；`POST :id/activate` 置顶 |
| `GET /api/repos/:id/{status,log,diff,show,branches,tags,remotes,graph,file,stashes}` | 只读，**不经过** executeTool（直接 GitService） |
| `POST /api/repos/:id/tools/:tool` | 写操作，走 executeTool |
| `GET /api/tools`、`GET/PUT /api/settings` | 工具表与权限；GET 可带 `?repoId=` 与 `validateToken=1`。`mr` 含该仓开单方式、`defaultRemote`、当前仓 remotes / host、当前域名凭证掩码、CLI 探测与可选校验摘要；PUT 可改 `permissions` 和/或该仓 method / `defaultRemote` / 按 host upsert 或删除 |
| `GET /api/logs` | 审计分页 |
| `GET /api/events` | SSE：`repo-changed`、`log`，15s ping |
| `GET/POST /mcp` | MCP Streamable HTTP |
| `GET /docs` | Swagger UI；REST 摘要 + 各工具 `POST .../tools/:name`（由 TOOL_DEFS 生成）。通用 `POST .../tools/:tool` 与 `/mcp` 不进文档 |
| `/` | 静态 `web/dist`；SPA fallback（hash 路由；跳过 `/api` `/mcp` `/docs`） |

`resolveWebDist` 按优先级找 `index.html`：源码布局 `packages/web/dist` → 发布布局 `dist/web` → 若干兼容路径。开发时 Vite `:5173` 代理 `/api` 与 `/mcp` 到 daemon。

只读 REST 与 MCP 只读工具数据同源（同一 GitService），但 REST 只读不写审计；打开仓库、activate、经 tools 的调用会记日志。

### 6.9 前端状态同步

1. `App.vue` 启动：health → 拉仓库列表 → `branches.load()` → 订 SSE。换仓库或 revision 变化时再拉分支列表（请求去重）。
2. SSE 到达 → `useRevision().bump()` → Status / History / Logs `watch(revision)` 刷新；合并页若已有调查结果则标「矩阵可能过期」（不自动重跑）。Agent / MCP 不订 `/api/events`，收不到这些事件。
3. 当前仓库：`localStorage git-cockpit:currentRepoId` 优先，否则列表第一项（最近打开）。
4. 分支数据：`useBranchesStore` 一份扁平列表；状态页侧栏、合并页 / 历史的树选共用，页面只做 scope 过滤（本地 / 远程 / 全部）。合并页单对与矩阵共用 `useMergeSessionStore`，切模式不丢调查结果与冲突队列。

## 8. 风险把控

### 8.1 风险矩阵

| 风险类别 | 等级 | 应对（已落地部分） |
|---------|------|-------------------|
| Git 误操作丢数据 | 高 | 高风险默认禁用+审批；执行前 stash+备份分支；dry-run+二次确认 |
| 命令注入 | 高 | simple-git 数组传参；路径/ref 校验 |
| 宿主 Agent 误调危险操作 | 中高 | 默认禁用；工具 description 标明风险；instructions 要求先 dry_run |
| 预演误改工作区 | 高 | 只用 merge-tree；落盘只用独立 worktree |
| 并发损坏索引 | 中 | 每仓库串行队列；写前检查 index.lock；同 daemon 内 Web/MCP 共用实例 |
| 敏感信息泄露 | 中高 | 审计脱敏（password/token/authorization）；设置快照同样脱敏 |
| 远程误推送 | 中 | 普通 push 非强制；force 用 `--force-with-lease` 且默认禁用 |
| 大仓库性能 | 中 | log maxCount 上限；diff 2MB 截断；历史条数前端可选 |
| stdio 破坏唯一后端 | 中 | 文档约定：多客户端共享请用 `start` + `/mcp` |

未落地的部署与安全项见本文 §13，此处不列规划清单。

### 8.2 安全机制摘要

- 三级工具 + 配置开关，无独立审批工单系统。
- 写操作 dry-run 返回 `{ dryRun, command, args, affectedFiles, risk, note }`。
- 高危自动备份见 6.6。
- 日志：时间、source、工具、仓库路径、脱敏参数、结果、耗时、是否 dry-run。

## 9. 数据与配置

数据目录默认 `~/.git-cockpit`（`GIT_COCKPIT_DATA_DIR` / `storage.dataDir`）：

| 文件 | 内容 |
|------|------|
| `config.json` | 服务端口、git 并发、权限、日志脱敏词、`mr.repoMethods`（按仓库路径的开单方式）、`mr.hosts[]`（按 hostname 的 Token） |

配置合并：`DEFAULT_CONFIG` ← 文件 ← 构造期 overrides，再 `normalizeMrConfig`（旧 `githubToken`/`gitlabToken` 迁到 `hosts`；旧 `method: auto` 迁成 `browser`）。损坏的 JSON 不阻断启动。`PUT /api/settings` 允许改 `permissions`，以及按当前仓写 `repoMethods`、改 `defaultRemote`、按 host upsert 或删除。snapshot 中 Token 显示为 `[REDACTED]`。

默认权限（`packages/core/src/types.ts`）：

```json
{
  "server": { "port": 3000, "host": "localhost" },
  "storage": { "dataDir": "~/.git-cockpit" },
  "git": {
    "maxConcurrentOperations": 1,
    "backupOnDangerousOps": true,
    "allowedRepos": []
  },
  "permissions": {
    "disabledTools": [
      "git_reset_hard", "git_clean", "git_push_force",
      "git_branch_delete_force", "git_rebase"
    ],
    "requireApprovalFor": [
      "git_reset_hard", "git_clean", "git_push_force",
      "git_branch_delete_force", "git_rebase"
    ],
    "dryRunDefault": false
  },
  "logging": {
    "level": "info",
    "redact": ["password", "token", "authorization"]
  },
  "mr": {
    "method": "browser",
    "defaultRemote": "origin",
    "hosts": [],
    "repoMethods": {}
  }
}
```

`allowedRepos` 字段已预留，打开仓库时尚未强制校验（规划见迁移方案 §10.3）。

### 11.3 npm 发布（与代码一致）

发布自动化在 **单个** `.github/workflows/release.yml`（两个 job，`release-mcp-server` `needs: release-core`），**不是**历史上的两个独立 workflow。

| 包 | tag | 判据 |
|----|-----|------|
| core | `core-v{version}` | 远程无此 tag 才 publish |
| mcp-server | `mcp-server-v{version}` | 同上 |

设计要点：
- **tag 在 publish 成功之后才推送**，表示「已发布」而非「试过了」；失败可原样重跑，不浪费版本号。
- 必须 `pnpm publish`：只有 pnpm 会把 `workspace:^` 改成真实 semver。
- mcp-server job 会先 **build core**（全新 checkout 无 `dist`），再 build web，再 publish mcp-server（`prepublishOnly` 复制 `dist/web`）。
- 因 job 顺序保证 core 先发，**不再**在 mcp-server 内轮询 `npm view`。
- 触发：push `master`/`main` 或 `workflow_dispatch`。Secret：`NPM_TOKEN`。
- core `0.x` 的 caret（如 `^0.1.0`）只覆盖 0.1.x；core 升 minor 时需同步 mcp-server 依赖范围。

core 构建后 `postbuild.mjs` 把 esbuild 剥掉的 `from "sqlite"` 改回 `from "node:sqlite"`。

失败重试、本地 dry-run 核对 tarball、镜像延迟等细节见 [release.md](./release.md)。

当前按本地单用户 daemon 设计，默认 `host=localhost`。远程多租户不在已实现范围内。

## 12. 注意事项与开发关键点

1. **唯一后端**：日常多人/多客户端应使用 `start` + HTTP MCP，避免多个 stdio 进程各写同一仓库。
2. **写操作收口**：新工具只加 `TOOL_DEFS` + GitService 方法，不要在 Web 路由里直接调 git。
3. **只读 REST 无审计**：若需要「谁看过 diff」审计，应改为走 executeTool 或补日志。
4. **打包**：core 必须 external `node:sqlite` 并跑 postbuild；mcp-server 必须 shebang（`cli-entry.js`），且 core/SDK/fastify/zod 不 bundle。
5. **静态资源**：发布包靠 `dist/web`；源码开发靠 `packages/web/dist` 或 Vite 代理。
6. **Windows**：bin 无扩展名 + shebang，Git for Windows 才能找到 `git cockpit`；纯 `.cmd` 不会被 git 的 PATH 查找命中。
7. **体验**：无仓库时禁用写按钮；远程操作失败用 GitOperationError 友好文案（如「请先拉取」）。

## 15. 总结

Git Cockpit 把 **MCP 工具、Web API、CLI** 收束到同一套 `Runtime` + `executeTool` + `GitService`。宿主聊天窗口里的 Agent 与网页点按钮走同一套权限、预览、备份和审计。合并预演不碰工作区；多分支可矩阵扫描并建议合入顺序；从矩阵选边只记本地临时分支，回矩阵再推送、开 MR；侧栏单对仍可落盘并推送。落盘走独立 worktree。本产品不内置对话模型。发版以 tag-after-publish 的单 workflow 为准。尚未落地项见本文 §13 与 [insight迁移方案.md](./insight迁移方案.md)。
